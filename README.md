
# taronja-gateway-clients

This repository provides autogenerated API clients for interacting with the [Taronja Gateway](https://github.com/jmaister/taronja-gateway) service.

## What is Taronja Gateway?

Taronja Gateway is a backend service for managing users, credits, authentication tokens, and request statistics. For more details, see the [Taronja Gateway GitHub](https://github.com/jmaister/taronja-gateway).

## Go Client Usage

### Installation

```bash
go get github.com/jmaister/taronja-gateway-clients/go
```

```go
import client "github.com/jmaister/taronja-gateway-clients/go"
```

The whole package (except `session.go` — see below) is generated by
[oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) straight from
the gateway's own OpenAPI spec, so every operation the gateway exposes has
a corresponding method here, named after that operation — `ListUsers`,
`CreateToken`, `GetCurrentUser`, `AdjustUserCounters`, and so on. Browse
`go/apiclient.gen.go` (or the gateway's own `api/taronja-gateway-api.yaml`)
for the full list; this section covers the parts that are the same for
every one of them: which of the two client types to use, and how to
authenticate a request.

### `Client` vs `ClientWithResponses`

Every operation exists in two forms. Prefer `ClientWithResponses` unless
you have a specific reason not to — it does the same HTTP call but also
decodes the body for you:

- **`Client`** (`NewClient`) — each method returns a raw `*http.Response`.
  You read and decode `resp.Body` yourself. Useful if you want streaming
  access to the body, or need a response header the typed wrapper doesn't
  surface.
- **`ClientWithResponses`** (`NewClientWithResponses`) — each method
  returns a typed `*XxxResponse` with the body already decoded into
  `JSON200`/`JSON401`/etc. fields matching that operation's documented
  status codes, plus the raw `Body []byte` and `HTTPResponse` if you need
  them too. This is what the rest of the examples below use.

```go
cli, err := client.NewClientWithResponses("https://your-taronja-gateway-server.com/")
if err != nil {
	panic(err)
}

resp, err := cli.GetCurrentUserWithResponse(context.Background())
if err != nil {
	panic(err) // a transport-level error — the request never got a response
}
if resp.JSON200 == nil {
	// The call went through, but didn't return 200 — resp.JSON401 (or
	// whichever field matches the operation's other documented statuses)
	// tells you what did, and resp.Status()/resp.StatusCode() give the
	// raw HTTP status either way.
	log.Fatalf("unexpected status: %s", resp.Status())
}
fmt.Println("authenticated as:", *resp.JSON200.Username)
```

### Authenticating requests

Every generated method takes optional `reqEditors ...RequestEditorFn` —
callbacks that get to mutate the `*http.Request` right before it's sent.
That's also how you attach authentication, since neither `NewClient` nor
`NewClientWithResponses` takes credentials directly. Two patterns cover
most cases:

**Forwarding a user's own session** (cookie-based, same auth a browser
talking to the gateway directly would use) — useful when your backend is
itself already holding a session cookie or token forwarded to it by the
gateway (see "Reading the forwarded session" below) and needs to make a
gateway API call *as that same user*:

```go
forwardSession := func(ctx context.Context, req *http.Request) error {
	req.AddCookie(&http.Cookie{Name: client.CookieSession, Value: sessionToken})
	return nil
}

resp, err := cli.GetCurrentUserWithResponse(context.Background(), forwardSession)
```

**Using an admin/server API token** (bearer auth) — for server-to-server
calls that need admin-level access (listing users, creating API tokens for
other users, etc. — see the gateway's own README for which operations
require it):

```go
withAdminToken := client.WithRequestEditorFn(func(ctx context.Context, req *http.Request) error {
	req.Header.Set("Authorization", "Bearer "+adminToken)
	return nil
})

// Passed to NewClientWithResponses, this applies to every call made
// through cli — no need to repeat it per method call.
cli, err := client.NewClientWithResponses("https://your-taronja-gateway-server.com/", withAdminToken)
if err != nil {
	panic(err)
}

resp, err := cli.ListUsersWithResponse(context.Background())
if err != nil {
	panic(err)
}
if resp.JSON200 == nil {
	log.Fatalf("unexpected status: %s", resp.Status())
}
for _, user := range *resp.JSON200 {
	fmt.Println(user.Id, user.Username)
}
```

A `RequestEditorFn` passed to `NewClientWithResponses`/`NewClient` (via
`WithRequestEditorFn`) applies to every call made through that client; one
passed directly to an individual method call (like `forwardSession` above)
applies to just that call. Both can be used together, and either can set
whatever else a request needs — headers, query params via `req.URL`, etc.

### Reading the forwarded session in a backend service

Every request Taronja Gateway proxies to a backend service carries the
authenticated session as a JSON header (`X-User-Data`), plus a plain
`X-User-Id` header for when that's all a route needs. `go/session.go`
(hand-written, not generated — see its own top-of-file comment) gives you
a ready-made `Session` type and a small helper instead of hand-copying
the shape yourself:

```go
import (
	"net/http"

	client "github.com/jmaister/taronja-gateway-clients/go"
)

func handler(w http.ResponseWriter, r *http.Request) {
	session, err := client.ParseSessionHeader(r)
	if err != nil {
		// No X-User-Data header — either this request didn't come
		// through the gateway, or the route doesn't require auth.
		http.Error(w, "unauthorized", http.StatusUnauthorized)
		return
	}
	fmt.Fprintf(w, "hello, %s", session.Username)
}
```

`client.Session` mirrors `db.Session` from the gateway's own repository
field for field — see its doc comment for exactly which fields exist and
why a couple of them (the ones inherited from GORM's embedded `Model`)
use PascalCase JSON keys while the rest use camelCase. `client.HeaderUserId`,
`client.HeaderUserData`, and `client.CookieSession` are the header/cookie
names themselves, exported for anywhere you need the raw name rather than
the parsed value.

`session.Token` is exactly the value the "forwarding a user's own session"
example above needs — a backend that parses the session off an incoming
request and then needs to call the gateway's own API *as that same user*
doesn't need a second cookie from anywhere; it already has it.
